# 依頼：ドッキリ用Webサイトの実装 ## 目的 友達に仕掛けるドッキリ用のWebサイトを、HTML/CSS/JavaScriptを1ファイルにまとめた `index.html` として実装してください。 ## 技術スタック・制約 - HTML / CSS / JavaScript を1つの `index.html` にまとめる（外部ファイル禁止） - 同フォルダに置いた `sound.mp3` を再生する - デプロイ先は **GitHub Pages**（静的サイト）。HTTPS前提 - スマホ（iOS Safari / Android Chrome）とPCの両方で動作すること - 初心者でも扱いやすい、コメント付きの読みやすいコードにすること ## 画面構成と遷移 ### 1. ローディング画面（初期表示） - 黒背景 - 中央にスピナー（CSSアニメーション） - テキスト：「ローディング中…（画面をタップしてください）」 - 下部に97%で止まる偽のプログレスバー - 画面のどこをタップ／クリックしても次のフェーズへ ### 2. スピーカーテスト画面（タップ直後、8秒間） - ダークグレーのカード型UI - タイトル：「スピーカーテスト中」 - サブテキスト：「スピーカーからテスト音を再生しています」 - **イコライザー風のビジュアライザー（縦バー9本）** を配置。実際の音声出力を `AnalyserNode` で拾ってリアルタイムにバーが反応すること - ビープが鳴るたびにカードの枠が青く発光するエフェクト - 下部に8秒かけて伸びるプログレスバー - この画面の目的は「音量を最大にさせること」だが、**「音量」「ボリューム」「大きく」といった直接的な誘導ワードは一切使わない**。あくまで「スピーカーテスト中」という体で、小さい音を鳴らし続ける。ユーザー自身が「音が出てるのに聞こえないな」と気づいて音量を上げる流れにする - 8秒経過で自動的にドッキリ画面へ ### 3. ドッキリ画面（自動遷移） - 赤背景（#e00000） - 画面全体が揺れるアニメーション - 白い波紋が広がるエフェクト（3つ、時間差） - 紙吹雪パーティクル（canvasで実装） - 巨大な文字「ドッキリ大成功！」（白、黒縁取り、揺れアニメ） - サブテキスト「びっくりした？ｗｗｗ」（黄色、点滅） - `sound.mp3` を最大音量で再生 - **フラッシュ演出は入れないこと**（点滅はNG） ## 音声の仕様 ### スピーカーテスト中のビープ - Web Audio APIの `OscillatorNode` でサイン波を生成 - 周波数・音量・間隔はデバイスで切り替える： - PC：800Hz、ゲイン0.05、間隔1100ms - モバイル：600Hz、ゲイン0.018、間隔1100ms（スマホのスピーカーは効率が良く、同じゲインだと大きすぎるため） - ビープ1回の長さ：160〜220ms - `AnalyserNode` に分岐してビジュアライザーに反映 ### sound.mp3の再生 - 再生前に要素のアンロック（後述）を行う - 音量は `volume = 1.0`（要素の最大値） - PCのみWeb Audio APIの `GainNode`（ゲイン2.5倍）＋ `DynamicsCompressor`（リミッター）で増幅する - **モバイルでは `createMediaElementSource` を使わないこと**（後述のハマりどころ参照） ## 既知のハマりどころ（必ず対処すること） ### ① iOSでスピーカーテストが進まない問題 `await audioCtx.resume()` を呼ぶと、iOS SafariではPromiseが永久に解決せず、以降のコードが止まる。 **対策：`await` せず `audioCtx.resume().catch(() => {})` のfire-and-forgetにする。** `runVolumeTest` は `async` にせず、通常の関数として実装する。 ### ② モバイルでsound.mp3が再生されない問題 iOS/一部Androidでは `
